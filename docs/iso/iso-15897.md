# ISO 15897 (locale identifiers)

## Summary

A string representing the country and language in the `xx_XX` format specified by ISO 15897 (for example `en_US`, `nl_NL`). Mollie uses this for the payment `locale` parameter (hosted payment pages and related language selection).

## Crate mapping

| Item | Location |
| --- | --- |
| Application enum | `mollie_rs::Locale` (`src/locale.rs`) |
| Generated wire types | `types::Locale` / `types::LocaleInner`, method query locale enums |
| Contract | [`docs/contracts/locale.md`](../contracts/locale.md) |

## Possible values (Mollie)

```text
en_US en_GB nl_NL nl_BE fr_FR fr_BE de_DE de_AT de_CH
es_ES ca_ES pt_PT it_IT nb_NO sv_SE fi_FI da_DK is_IS
hu_HU pl_PL lv_LV lt_LT
```

These are exposed as named `Locale` variants and as `Locale::POSSIBLE` (alias `Locale::HOSTED`). Prefer them for hosted payment pages and for `into_generated()` into the OpenAPI enum.

## Wire form

```text
ll_RR
```

| Part | Rule | Example |
| --- | --- | --- |
| `ll` | two **lowercase** language letters | `en`, `nl`, `de` |
| `_` | underscore separator (not hyphen) | `_` |
| `RR` | two **uppercase** region letters | `US`, `NL`, `DE` |

Valid: `en_US`, `nl_NL`, `de_AT`  
Invalid: `en-US`, `EN_US`, `en_us`, `en`

## Other ISO 15897 values

`Locale::parse` also accepts any other well-formed `xx_XX` (stored as `Locale::Other`). Unsupported UI languages may fall back to browser language. Converting non-possible values with `into_generated()` fails until the generated OpenAPI enum includes them.

```rust
use mollie_rs::Locale;

assert_eq!(Locale::parse("nl_NL")?, Locale::NL_NL);
assert!(Locale::NL_NL.is_possible());
assert!(Locale::parse("ja_JP")?.is_other());
assert!(Locale::parse("en-US").is_err());

let wire = Locale::NL_NL.into_generated()?;
# Ok::<(), mollie_rs::MollieError>(())
```

## Bank transfer note

For bank transfer, locale can influence which local Mollie bank account the customer is instructed to use (e.g. BE / DE / NL). Prefer an appropriate possible locale for conversion.
